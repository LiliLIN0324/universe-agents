# 软硬联调

## 选型从约束开始

不要先挑型号，先写这张表：

| 项 | 需求 | 备注 |
| --- | --- | --- |
| 工作环境 | 温度、湿度、粉尘、震动 | 决定工业级还是消费级 |
| 供电 | 电池 / 适配器 / PoE | 决定功耗预算 |
| 续航或散热 | 待机多久、满载多久 | 决定处理器档位 |
| 接口 | 串口 / 网口 / 无线 | 决定外围芯片 |
| 实时性 | 响应最慢能接受多少 | 决定要不要 RTOS |
| 量产 | 首批多少、几年 | 决定器件供货和封装 |

表填不满就不要选型。选完了才发现续航不够，是最贵的一种返工。

## 原理图评审看什么

按这个顺序，从会炸的不看到不会炸的：

1. **电源**：电压、电流余量、上电顺序、防反接、保险
2. **复位与启动**：复位电路、启动引脚、烧录口是否可用
3. **时钟**：晶振负载电容、走线
4. **通信电平**：3.3V 和 5V 混接、上拉电阻、终端电阻
5. **保护**：ESD、过压、热插拔
6. **测试点**：关键信号有没有留出测量点

最后一条经常被省掉，结果是调试时只能飞线。

## 固件分层

```
应用层：业务逻辑，不碰寄存器
服务层：协议解析、状态机
驱动层：传感器与外设的读写
板级：引脚、时钟、电源初始化
```

规矩：

- 应用层不直接操作寄存器。换一颗芯片，只该动驱动层。
- 每个外设的读写都要有超时。总线卡死不能把整个系统带停。
- 中断里只做最短的事，其余交给主循环或任务。

## 设备到服务器

设备上报不需要复杂，但要把三件事定死：

1. **设备身份**：每个设备一个唯一 ID，出厂写死
2. **数据格式**：字段、单位、精度、时间戳
3. **离线行为**：断网了缓存多少、重连怎么补

示例：

```json
{
  "deviceId": "SN-000123",
  "ts": 1767225600000,
  "metrics": { "temp": 23.5, "humidity": 41 },
  "seq": 10241
}
```

`seq` 单调递增，服务器按它去重和补漏。没有这个字段，重连时的重复数据会多算一遍。

## 协议怎么选

| 场景 | 用 |
| --- | --- |
| 设备连云端、要双向 | MQTT |
| 工业现场、PLC 对接 | Modbus |
| 板内芯片之间 | I2C / SPI |
| 与电脑或其他板子 | 串口 / USB |
| 手机近场控制 | BLE |

不要为「以后可能」上一个更复杂的协议。先能跑通，以后再换。

## 联调从哪开始

顺序不能跳：

1. **供电**：量电压，看发热
2. **能烧进去、能起来**：串口打印一句启动信息
3. **单个外设**：一个传感器读数正确
4. **总线**：多个外设一起，看有没有冲突
5. **联网**：连上服务器，收到一条数据
6. **双向**：服务器下发一条指令，设备执行

每一步都要能看到结果。第 5 步和第 6 步出问题时，九成的原因在第 1–4 步。

## 常见错误

- **用开发板跑通就以为成了**：换到自制板，电源和时钟全变。
- **引脚分配冲突**：软件里配了，硬件上已经占了。
- **没有超时**：一个传感器不响应，整机卡死。
- **只测一台**：十台里有一台的晶振稍微偏一点，现场才发现。
- **固件不带版本号**：现场一堆设备，没人知道哪台跑的是什么。
