# 画布看板

## 看板解决什么问题

文档按时间写，看板按**位置**摆。人找东西时，想的是「那个事在哪个格子里」，不是「那份文档第几页」。

所以做看板之前先回答：**别人打开它要找什么？** 找不出来，就不该做。

## 一张看板只装一件事

合格的主题：

- 这次上线，卡在哪、谁在等谁
- 这个项目，有哪几块、各自到什么程度
- 这批需求，分别在哪一列，谁负责

不合格：

- 「项目所有信息」
- 「团队看板」，但没说看什么

## 结构

大多数看板用三种结构之一：

| 结构 | 适合 | 例子 |
| --- | --- | --- |
| 列（状态） | 有明确流程 | 待办 / 进行 / 待验 / 完成 |
| 网格（维度） | 要横向比较 | 模块 × 阶段 |
| 分组清单 | 信息量大、不强调先后 | 按风险分组 |

列和网格不要混用。混在一起，读者会先花时间搞懂版式，才看到内容。

## 数据从哪来

这是看板最容易骗人的地方。

- 手工录入：会有过期，必须在卡片上显示「最后更新时间」
- 从文件读：要写清楚读的是哪个文件、多久同步一次
- 从接口读：接口断了要显示「数据没取到」，不能保留上一次的数字假装是最新的

**永远不要画一个会自己动的进度条。** 进度要么来自可核对的数据，要么就写「未估算」。

## 每个格子至少三样

1. **是什么**：一句话，不超过十五个字
2. **到哪了**：状态或数字
3. **谁在看它**：负责人或下一个动作

缺第三样，卡片就只是装饰。

## 点击能做什么

看板的价值在于点开：

- 点一张卡 → 看到详情、历史、相关链接
- 点一列 → 筛出这一列的
- 点一个人 → 看这个人的所有事

点开之后没有新信息，就不该做成能点的。

## 交付前自检

- [ ] 每张卡片的数字能被追溯到来源
- [ ] 空状态写了「还没有数据」而不是留白
- [ ] 数据取不到时显示错误，不显示旧数字
- [ ] 手机上看不漏关键信息
- [ ] 打印或截图出来，仍然看得懂

最后一条常被忽略：看板经常被截图发到群里，截图里没有悬停提示。

## 常见错误

- **什么都要放**：看板变成第二个文档库，没人再看。
- **假进度**：编一个 70%，比空着更糟。
- **只做电脑版**：开会时大家看的是手机。
- **配色就是分类**：颜色超过四种，就没人在意颜色了。
