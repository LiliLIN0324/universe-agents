# 可点原型

## 原型是给谁看的

同一个原型不能同时讨好三种人。先定读者：

| 读者 | 原型该有什么 |
| --- | --- |
| 自己 | 只要能点通主流程，别的都多余 |
| 团队评审 | 主流程 + 关键状态 + 两个难点页面 |
| 客户 / 老板 | 主流程 + 一屏真实内容，别有占位符 |

给客户看的原型里出现「Lorem ipsum」或者灰块，等于告诉对方「还没想清楚」。

## 先写令牌，再画页面

页面之前先定这几个值，后面所有页面都从这里取：

```css
:root{
  --ink:#1a1a1a;      /* 正文 */
  --ink-soft:#6b6b6b; /* 辅助 */
  --line:#e2e0da;     /* 分隔线 */
  --surface:#fff;     /* 卡片底 */
  --canvas:#f6f5f1;   /* 页面底 */
  --brand:#0f5c4a;    /* 主色，只有一个 */

  --fs-body:15px;
  --fs-cap:13px;
  --fs-h2:22px;
  --fs-h1:38px;

  --sp-1:8px; --sp-2:16px; --sp-3:24px; --sp-4:40px;
  --radius:10px;
}
```

规矩：

- 字号档位不超过五档，间距只用四的倍数。
- 主色只有一个。第二种强调色出现之前，先想想是不是可以用字重解决。
- 灰不能只靠一条 `--ink-soft`。至少要有「正文 / 辅助 / 禁用」三级。

## 状态必须做全

每个关键页面至少四个状态，缺一个评审时就会被问到：

1. **空**：第一次进来什么都没有
2. **正常**：有数据
3. **加载**：慢的时候长什么样
4. **出错**：网络断了、没权限

再补两个常见的：

- **部分失败**：三个里成功两个
- **超长内容**：名字三十二个字、列表三百条

只做「正常」的原型，上线后第一周一定出问题。

## 点哪里要真能点

原型里的每个可点元素都要有去处：

- 打开新面板 → 真打开
- 提交 → 至少走到成功或失败的提示
- 还没做的功能 → 按钮上直接写「未接入」，不要做成看起来能点却没有反应

不能点的东西不要画成按钮的样子。这是原型最容易留下的坑：评审通过，开发照着做，最后发现那个「按钮」只是个装饰。

## 交付物

1. 一个能双击打开的 HTML 文件，不依赖本地服务
2. 令牌写在文件最前面，标注清楚
3. 一份状态清单：每页有哪些状态、怎么切换

不需要 psd，不需要切图，不需要组件库。

## 常见错误

- **用截图代替原型**：看着像，但点不动，评审只能靠想象。
- **一个页面做三版配色**：评审时谁都不好意思说，最后选不出来。
- **只做主路径**：主路径从来不缺，缺的是岔路。
- **原型里放真实数据**：用了真实的手机号、真实的名字，展示时容易出事。用明显的假数据。
